| TD-018 | Every trading cycle silently crashed with `sqlite3.OperationalError: attempt to write a readonly database` for 36+ days (2026-09-17 onward) — zero new trades, signals, or decisions recorded the whole time — while every GitHub Actions run still reported `success` and the Watchdog still reported healthy | 2026-10-22 | **First fix attempt was incomplete — caught by actually re-dispatching and watching it fail again, not by inspection.** Initial root cause: `shutil.copy()` in 5 places (`bot/monitor/sync_db.py`, `.github/workflows/trade.yml` x2, `.github/workflows/retrain.yml`, `scheduler/startup_job.py`) also copies the source file's permission bits, so a freshly-restored `trades.db`/`trust_ledger.db` inherited the read-only HF cache blob's permissions. Fixed by `chmod`-ing the destination writable (if it already exists) before every copy, in all 5 sites — chmod is governed by ownership, not current mode, so this self-heals a poisoned destination every run without needing to separately purge the GitHub Actions cache. **Still pending as of this entry: a live dispatched run proving the chmod fix actually works** (CI is green; production proof is the one thing not yet confirmed). Also found and fixed 3 unrelated pre-existing CI failures blocking the dashboard deploy gate (2 non-deterministic `checked_at` comparisons, 1 test with a hardcoded date and an unfrozen clock). Added a second Watchdog check (`.github/workflows/watchdog.yml`) that alerts if the HF dataset repo's `last_modified` goes >96h stale — note this only catches multi-day silence, not a same-day run crashing every cycle; today's failure was only caught by manually dispatching and watching, not by any automated alert. |
